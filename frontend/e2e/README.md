# Browser verification

From `frontend`, run `npm run test:e2e`. By default, the suite uses installed Microsoft Edge in headless mode; no separate browser download is required for Edge. Alternatively, run `npx playwright install chromium` and set `PLAYWRIGHT_BROWSER_CHANNEL=chromium` before running the suite. The GitHub Actions workflow uses Chromium; the complete suite has also passed locally in Chromium and Edge.

Install both packages' dependencies, then run `npm run db:generate` and `npm run db:deploy:test` from `backend`. Configure `backend/.env.test` from `.env.test.example` with a `DATABASE_URL` whose database name ends in `_test`. Fixtures create unique student/admin accounts and courses and delete only those records after each test. Browser tests use their own JWT secret. Finish Prisma generation before starting browser tests: changing generated files while the watched API runs can restart it and interrupt a request.

The optional [local demo](../../docs/DEMO.md) uses a different _demo database and ports 3002/5174; these browser fixtures continue to create their own data in _test. The backend demo-seed tests create a temporary database and require CREATEDB, while this browser suite does not seed or reset the local demo.

The suite starts its own API at `http://localhost:3001` and Vite at `http://localhost:5180`. It refuses to reuse an existing server. The regular app defaults remain API port 3000 and frontend origin 5173. Optional app settings are `PORT`, `CORS_ORIGIN`, and frontend `VITE_API_URL` (including `/api`).

Run `npm run test:tooling` for the lint-glob/ignore/rule compatibility checks protecting the scoped minimatch override. Run `npm run typecheck:e2e` to type-check the browser tests. Run `npm run test:e2e -- --headed` to watch the browser, or `npm run test:e2e -- --grep "quiz"` to select scenarios.

Set `PLAYWRIGHT_PREVIEW=true` to build and test production assets with Vite preview. The config sets the isolated test API URL during that build. For example, in PowerShell: `$env:PLAYWRIGHT_PREVIEW = 'true'; npm run test:e2e`. Remove that environment variable to return to the default development server. CI selects preview mode with Chromium; local verification also covers Edge with the development server and Strict Mode.

Final combined local verification (point 6, 2026-11-07) reran all 55 scenarios successfully in Chromium production preview and Edge development/Strict Mode after the demo batch. The separate demo remained on 3002/5174. See [the validation record](../../docs/VALIDATION.md) for the complete check results and pending remote-CI status.

The 55 scenarios cover public access, login/session restoration/logout, enrollment, manual completion, quiz lookup failures/retry, SPA navigation while a quiz lookup is delayed, keyboard radio selection, partial and perfect scores, duplicate submission prevention, failed retakes, unavailable progress, returning to the lesson/course after a perfect score, admin ordering/conflicts/deletion, single-choice answer authoring, draft preview, failed and successful publication, cancellation of a delayed login, exact completion counts despite a rounded legacy percentage, mobile catalog/dashboard/admin navigation/layout, and all four admin authoring forms with enlarged text. The return-to-course scenario checks the completed lesson, Review action, progress changing from 0/2 to 1/2 (50%), correct Continue destination, and persistence after reload. Tests using account fixtures also check for uncaught browser errors.

Quiz-history scenarios cover protected/lazy loading, desktop/mobile personal navigation for both roles, real partial/perfect submissions and saved score ordering, per-quiz/all-history filtering and reload, isolation from other users/drafts, unfinished attempts, read failure/retry/refresh, invalid URL filters without broader fetching, and cancellation of every delayed old-filter request in Strict Mode. Captures quiz-history-desktop.png and quiz-history-mobile.png are reviewed at 390px with enlarged root text. Historical scores do not serve as lesson-completion evidence. HTTP authorization/filtering coverage is in backend/tests/quiz-history.api.test.ts.

UI recovery scenarios cover public/authenticated unknown routes, keyboard navigation and primary-button contrast, read retries on public/learner/admin pages, preserved search/filter state, independent lesson progress versus quiz checks, one saved attempt across perfect-score progress retries, and cancelled delayed progress retries. Captures include not-found-desktop-focus.png, not-found-mobile.png and quiz-progress-retry-mobile.png. The public navigation wraps at 390px with a 20px root text size.

Quiz-refactoring scenarios verify submit failure/retry without losing selections, disabled controls and duplicate prevention, cancellation of a pending submit, cancellation of post-submit completion verification after navigation, and exact passing counts despite a legacy rounded 100% score. Captures include quiz-submit-error.png plus the existing perfect-quiz.png and mobile-quiz.png.

Course-details scenarios check enrollment failure/retry and duplicate prevention, unknown progress without a guessed percentage/Continue action, recovery of saved progress, cancellation of all old metadata requests (including Strict Mode duplicates), a pending enrollment during history navigation to another course, and review actions after completing/reloading a course. Captures include course-details-progress-unknown.png and course-details-completed-mobile.png.

Route-loading scenarios verify that Home does not download the catalog, lesson or admin page modules; a delayed catalog download keeps navigation visible and announces loading. Failed downloads show a recovery action and reload can retry. Authorization redirects run before protected page modules download. The same module intercepts support development source URLs and production hashed assets.

Admin scenarios verify inline validation without invalid HTTP writes, Escape/Cancel and focus restoration, delete failures/retry, duplicate prevention, course cascade deletion, checklist retry/stale-read cancellation and publication after correction. Confirmations use the integrated HTML dialog. Captures include publication-checklist.png and delete-dialog-mobile.png. See [the admin guide](../../docs/ADMIN_AUTHORING.md).

Lesson scenarios cover Markdown structure, legacy line breaks, escaped HTML, filtered script URLs, keyboard-focusable code scrolling, desktop/mobile layout, live/saved admin preview, navigation gaps/boundaries/single-lesson courses, retry independent of completion and cancellation of stale curriculum requests. The delayed-navigation test holds all requests for the old lesson, including Strict Mode duplicates, and checks they are cancelled. Example captures are lesson-markdown-desktop.png, lesson-markdown-mobile.png and lesson-editor-preview.png. See [the content guide](../../docs/LESSON_CONTENT.md).

Shared UI scenarios verify catalog loading, search and clearing, All/My/Available filter states, guarded enrollment, progress-bar values, loading errors versus empty states, and published-only public catalog access during admin sessions. The legacy rounded-percentage scenario checks the Completed badge and Continue/Review actions within the dashboard card. The suite captures catalog-ui.png, courses-ui.png and dashboard-mobile-ui.png under the corresponding test's output directory for visual review.

Mobile overflow assertions report the page width, viewport width and overflowing elements. The enlarged-text regression sets the root text size to 24px at a 390px viewport: this reproduces the implicit-grid-column overflow seen in Linux CI independently of the local system font. Admin grids explicitly use one shrinkable column below the desktop breakpoint. Deletion scenarios wait for removed content to disappear before the next mutation or fixture cleanup. Answer-option saves assert the persisted option paragraph and ready Add option button, so the editor value cannot produce a false successful save.

Screenshots, failure traces and the HTML report are written to ignored `test-results/` and `playwright-report/` folders. Open the latest report with `npx playwright show-report`.
